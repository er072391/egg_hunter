
仕組みと動作の流れ

1. 本命コードの配置（Eggの設置）
攻撃者はあらかじめ、Webサーバーの他の入力フォームや通信ヘッダー（User-Agentなど）を利用して、システム上のどこか別のメモリ領域に本命のシェルコードを送り込んでおきます。
このとき、コードの先頭に w00tw00t や EGGSEGGS のような、一目でわかる「4〜8バイトの特殊な文字列（目印＝Egg）」を付与しておきます。
2. 小さなハンターの注入
容量が少なくて本命が入らなかった脆弱なバッファ（40バイトの隙間など）に対して、「メモリ全体をスキャンして w00tw00t という文字を探せ」という命令だけが書かれたごく短いコード（Egg hunter） を注入し、実行させます。このハンターコード自体は、約30〜40バイト程度と非常に小さいため、狭い隙間にも収まります。
3. メモリの探索と実行
実行された Egg hunter は、パソコンのメモリ（VAS: 仮想アドレス空間）を端から猛スピードで探索していきます。
そして、事前に入り込ませておいた目印（w00tw00t）を見つけると、その直後にある本命のシェルコードへと処理をジャンプ（移行）させ、実行を完了させます。
